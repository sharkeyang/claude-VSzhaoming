# 研究仓位管理

> 来源：[Anthropic金融Skill拆解③：组合管理](https://mp.weixin.qq.com/s/Jtxksl4vYaGwO-BpMFFUQw) — 道以研究院/小以AI
> 整理日期：2026-07-19

## 一、核心框架

Anthropic 把组合管理拆为 **3 个 Skill**，占私募投研/风控负责人约 **35% 的日常时间**：

| Skill | 中文 | 核心功能 | 传统耗时 | AI 辅助后 |
|-------|------|----------|----------|-----------|
| portfolio-monitoring | 持仓监控 | 收益对比、行业贡献、风险指标、实时告警 | 1-1.5h/天 | 15min/天 |
| risk-attribution | 风险归因 | Brinson 归因、因子/风格归因、漂移检测 | 4-8h/月 | 2h/月 |
| rebalancing | 再平衡建议 | 调仓建议生成（文章未完整展示） | — | — |

### 核心设计原则

> AI 只负责"指标计算+异常标注"，不负责"买卖建议"。是否调仓由人决定。

这与昭明项目"人做决策，AI 做苦力"的理念一致。

## 二、持仓监控（portfolio-monitoring）详解

### 2.1 能力拆解

1. **收益与基准对比**：自动生成组合收益 vs 基准、主动收益（active return）、信息比率（information ratio）
2. **行业贡献拆解**：把行业对主动收益的贡献以基点（bps）计呈现
3. **风险指标面板**：Sharpe、beta、最大回撤（max drawdown）、active share 一键算出
4. **实时跨资产定价**：通过 LSEG MCP 拿到实时价格

### 2.2 国内落地差异

| 维度 | 美国 | 中国 |
|------|------|------|
| 数据源 | FactSet/LSEG 统一覆盖 | Wind/Choice/CTP 分散 |
| 告警渠道 | Slack/邮件 | 企业微信/钉钉（需留痕审计） |
| 智能日报 | 有成熟方案 | 几乎空白 |

### 2.3 国内痛点

- 数据分散，多终端拼
- 指标手算易错（active share、信息比率）
- 无实时告警，偏离事后才发现
- 报告重复劳动，框架固定但每次重拉数

### 2.4 改造路线图

| 阶段 | 目标 | 量化指标 |
|------|------|----------|
| 近期 | 自动拉取+指标看板+日报生成 | 监控准备 60min→10min；指标错误率<1% |
| 中期 | 异常检测+实时告警+留痕 | drift 阈值触发自动推企微 |
| 远期 | 推送集成+人机闭环 | 手机审核，3 分钟看完，全程留痕 |

## 三、风险归因（risk-attribution）详解

### 3.1 能力拆解

1. **行业贡献拆解（bps）**：标准做法
2. **Brinson 模型**：拆"资产配置贡献"vs"个股选择贡献"vs"交互贡献"
3. **因子/风格归因**：看收益来自哪个风格因子（成长/价值/动量）

### 3.2 核心设计原则

> 归因的核心是"拆解到可解释的最小单元"。归因报告必须能回答"每一分收益来自哪里"，否则就是黑盒。

### 3.3 国内落地差异

- 归因框架不统一（Brinson/多因子/行业拆分），AI 需支持可定制框架
- **风格漂移检测更关键**：国内私募"挂羊头卖狗肉"现象更常见，active share 变化检测是合规和信任的刚需，但多数工具不做
- 持仓数据来自 PB 系统，常有 T+1 延迟，需统一数据口径

### 3.4 改造路线图

| 阶段 | 目标 | 量化指标 |
|------|------|----------|
| 近期 | 归因库+自动报告+漂移检测 | 归因报告 4-8h→2h；完整性 90%+ |
| 中期 | 可定制框架+情景压力测试 | 支持自定义归因框架，跑历史情景 |
| 远期 | 持续归因+趋势跟踪 | 从"月末一次性"变"持续滚动" |

| ZPY Python 接口 | `PX算研_ZPY接口.bas` + `.py` | ✅ 已有基础 |

### 4.2 最直接可落地的机会

1. **花册数据 + LLM 日报**：ROS 据管的花册数据 + 算展结果 → Python 调用 LLM 生成每日/每周监控总结
2. **偏离阈值告警**：护型体系（位1/位4）已有分类基础，可叠加行业/个股偏离度计算
3. **归因复用已有计算**：RAP 算展 + ZAL 算比已有大量算展结果，可改造做 Brinson 风格归因
4. **告警留痕**：企业微信/钉钉推送 + 落库，可审计

### 4.3 核心差距

项目已完成 VBA 算展/数据层，**最缺的是"自动化报告 + 偏离告警"中间层**——这正是 Anthropic 这套 Skill 设计要解决的问题。
